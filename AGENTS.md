# LangTeacher

## Stack

- **Language / Runtime**: Swift 6.4 (Swift 6 language mode, strict concurrency), Xcode 27.1, macOS 26+ only
- **Framework**: SwiftUI with `@Observable` feature models; single window `NavigationSplitView` + `Settings` scene
- **Key dependencies**: GRDB.swift 7 (one SQLite file, `DatabasePool`, WAL), swift-subprocess 1.x (runs the local `claude` CLI), `os.Logger`
- **Package manager**: Swift Package Manager (local package `Packages/LangTeacherKit`); Xcode project generated by XcodeGen from `project.yml`
- **Tests**: Swift Testing per package target via `swift test`; XCUITest `AppUITests` arrives at Slice 1
- Full decision: [docs/specs/0001-stack-architecture/index.md](docs/specs/0001-stack-architecture/index.md)

## Build approach

**Tracer Bullet**: each slice runs end to end through screen, Claude, and saved data; later slices thicken one strand of a thread that already works.

## Rules

- **Clean Architecture, mapped to modules**: `Core` is the domain (entities, value objects, teaching rules, `Sendable` service protocols; Foundation only). `Persistence` (GRDB) and `ClaudeBridge` (CLI) are infrastructure that implement `Core` protocols. `Features` is presentation and imports `Core` only. `App/AppEnvironment.swift` is the composition root. Dependencies point inward; `Package.swift` enforces it.
- Business rules (grading, quiz shuffling, spacing) live in `Core` as plain value types that enforce their own invariants; feature models only orchestrate service calls.
- No GRDB, Subprocess, or prompt types cross a module boundary: pass `Core` value types and `AsyncStream`s of `Sendable` values.
- Services go into models through initializers or a SwiftUI `@Environment` entry. No singletons, no global database handle.
- Only `ClaudeBridge` launches a process or builds a prompt. The app (not Claude) shuffles quiz options.
- `App` and `Features` default to main actor isolation; `Core`, `Persistence`, `ClaudeBridge` stay nonisolated.
- Packages never check the build type; only `AppEnvironment` uses `#if DEBUG` (picks `LangTeacher-Dev` vs `LangTeacher` data folder).
- No third party dependency beyond GRDB and swift-subprocess without a spec or explicit OK. Edit `project.yml`, never the generated project.
- Every `public` type and member in LangTeacherKit has a `///` doc comment.
- Each module throws its own typed error enum with a user facing message; no stringly errors, no silent `try?` on real work.
- Accessibility baseline on every screen: labelled controls, Dynamic Type, VoiceOver order, WCAG AA contrast.
- Testing gate: each feature ships Swift Testing tests in the matching package target, using fakes of `Core` protocols; Persistence tests use a real (in memory or temp folder) database.
- Commits follow Conventional Commits, scoped by module: `feat(bridge): …`, `fix(store): …`.

## Tooling

Chosen, installed by `/develop tooling`: built in `swift format` (layout) + SwiftLint via Homebrew (smells, custom rules such as no `GRDB`/`Subprocess` import in `Features`). Pre-commit hook runs format check + lint (no tests). CI: not yet; add when a GitHub remote exists.

- Config: `.swift-format` (4 spaces, 120 columns, `///` docs required on every `public` declaration), `.swiftlint.yml` (rules that overlap swift format are off; `custom_rules` enforce the module boundaries above as errors), hook script in `.githooks/pre-commit`. A new boundary rule goes in `.swiftlint.yml` `custom_rules`, scoped with `included`/`excluded` path regexes and `match_kinds` so comments never trip it.
